# VPS REALITY 与 Clash 订阅

这是当前项目的技能。默认中文，按用户本次要求执行；创建技能、解释配置或仅生成本地文件，不代表授权连接、修改某台 VPS。

## 先确定执行范围

- **实际部署或远程维护：** 收集可用 SSH 认证，执行远程检查、目标站验证、安装和端到端验收。
- **仅本地准备：** 不需要 SSH 密码、不连接 VPS。按已有地址生成文件；SNI 可采用用户给出的候选值，缺失时说明暂用的候选值并标记未验证。交付时说明尚未验证目标站、内核、出口和订阅可达性，不把拟用地址称为已上线订阅。
- **仅解释分流或 TUN：** 读取现有配置后回答，不启动部署流程，也不索要凭据。

## 输入与产物

- 必须有 VPS 公网 IP 或域名；实际远程部署还需要可用的 SSH 认证。SSH 端口、用户名优先沿用用户提供的信息；未提供时说明拟使用的默认值 `22`、`root`。地址缺失就先收集地址，不猜测目标。
- SSH 密码通过私密凭据工具单独收集；可用的 SSH agent、密钥或私密凭据文件可直接复用。住宅 SOCKS5 另用一张私密卡片，接收完整 URL；不把两种凭据挤在同一输入框。不在聊天、命令参数、日志或技能文件中复述密码。
- **住宅代理可选。** 用户未提供时默认只部署一个 VPS 出口，不反复索要住宅地址、不创建虚假住宅节点。提供住宅代理后才增加第二个出口。
- **分流配置必需。** 内置 [assets/Clash-VPS-住宅.yaml](assets/Clash-VPS-住宅.yaml) 是脱敏模板，含本项目用户提供的全部 247 条规则，默认直接使用，无需再次上传。用户另给规则时，按原顺序替换并校验引用，不静默拼接或改优先级。
- 始终交付名为 **`Clash-VPS-住宅.yaml`** 的完整配置，即使没有住宅出口也保持此文件名。正常部署另交付能实际下载的 HTTPS 订阅地址；只有配置准备、托管受阻时，明确区分本地文件与已发布订阅。
- 客户端只包含可用的 VLESS 节点。住宅 SOCKS5 的地址及认证留在 VPS 服务端，住宅链路为“客户端 → VPS 的 REALITY/Vision → 住宅 SOCKS5 → 目标网站”。

## 执行流程

以下远程步骤用于实际部署；仅本地准备只执行配置生成和可用的离线校验。

1. **建立连接与检查现状。** 先检查 SSH 握手，再登录读取系统、架构、时间、现有服务、监听端口、防火墙。确认拟用代理端口和订阅端口可用；保存将修改的已有文件及恢复方法。已有服务存在时优先隔离安装，不盲目运行一键脚本、覆盖现有代理或清空防火墙。
2. **核实版本与 REALITY 目标。** 部署前查官方发布和配置文档，下载匹配架构的受支持版本并校验官方摘要。用 VPS 实测候选 SNI 的 TLS 1.3、证书主机名和 HTTP/2；不要把某次示例站点当作永久推荐。有关 Mihomo 版本门槛和密钥交换选项，先读 [references/deployment.md](references/deployment.md) 的“握手兼容”。
3. **本地生成配置。** 使用 [scripts/build_configs.py](scripts/build_configs.py)，依赖 `PyYAML`、`cryptography`，优先在临时虚拟环境安装。只把非敏感地址、端口、SNI 放入命令参数；住宅凭据传私密文件路径。输出目录必须是本次独立的私密目录。脚本会生成并保留本次 UUID、X25519 密钥和订阅令牌，重试时复用同一输出目录，不无故轮换凭据。
4. **安装与启用服务。** 按实际系统适配，将 `server.json` 安装到仅服务账户可读的位置，用独立服务管理进程、重启和开机启动。每个入站用户和客户端节点都要有 `flow: xtls-rprx-vision`。有住宅时，以不同 UUID/用户标签准确路由至 SOCKS5；住宅失败时不要偷偷回落到 VPS 出口。
5. **托管 HTTPS 订阅。** 将完整 YAML 放在随机令牌路径后，用可信证书提供下载，不列目录、不记录带令牌的访问路径。域名或 IP 证书、ACME 引导配置和续期流程见 [references/deployment.md](references/deployment.md) 的“订阅与续期”。证书就绪后再加载生成的 TLS 配置。
6. **验证真实行为。** 完成下方验收；失败时根据证据修正。同一操作在没有新证据或配置变化的情况下连续失败两次，就停止相同重试，保留诊断、继续可独立完成的准备，并说明阻塞点。不要用旧核心盲目降级来掩盖兼容问题，不把“配置校验通过”当成“已经能上网”。

生成示例；部署时使用用户的目标和已验证的 SNI；离线准备可用明确标注未验证的候选 SNI：

```bash
python scripts/build_configs.py --server 198.51.100.10 --sni www.apple.com --output /tmp/reality-deploy-private
```

有住宅时追加 `--residential-secret-file /path/to/private-socks-file`。用户给出新的规则文件时，可追加 `--rules-file /path/to/rules.yaml`；规则目标和策略组必须完整对应。

脚本只生成文件，不执行 SSH、安装、发布或自动修改客户端。它检查基础结构、策略引用与分组循环，不代替内核对所有规则类型及参数的校验。生成的 `subscription.url` 在实际 HTTPS 服务可访问之前只是拟用地址。

## 验收与交付

- 服务端配置测试通过；服务实际运行且开机启动已启用。确认当前加载的配置、端口和生成产物一致，关闭临时握手调试。
- 用 Mihomo 加载最终导出的配置，所有规则与策略组均有效；内置模板的 247 条规则顺序与正文保持一致。无住宅时应只有一个节点且无悬空的住宅引用，有住宅时应有两个节点。
- 从外部用默认 TLS 验证下载订阅，比较内容与交付文件一致，错误令牌路径返回拒绝或 404；不得通过跳过证书验证来冒充 HTTPS 验收通过。
- 通过完整的 VLESS/REALITY 客户端链路访问至少两个 HTTPS 目标，并记录每个节点实际出口。住宅预期出口应先从 VPS 经 SOCKS5 实测，**不能假设 SOCKS5 服务地址等于出口 IP**。确保测试请求真的通过本次代理端口。
- 确认证书续期定时器和 Web 服务重载钩子，执行一次续期演练；不能演练时如实说明未验证部分。
- 住宅默认仅启用 TCP。未完成 SOCKS5 UDP 与端到端验证，不宣称支持 UDP、QUIC 或所有流量。默认保留规则模式，`PROXY` 默认 VPS；解释 TUN 和全局模式时看参考中的“分流与 TUN”。
- 交付订阅地址、`Clash-VPS-住宅.yaml` 的本地文件链接、实际节点数量和出口，说明如何选住宅及实际限制。清理临时测试进程、私密输入文件和不再需要的本地私钥副本，保留用户需要的配置与服务器恢复资料。不要把本次部署的凭据、UUID、私钥、真实 IP 或订阅令牌写回技能。
